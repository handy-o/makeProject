### 카테고리탭

1. 도입: 프로젝트의 목적과 현재 컴포넌트의 역할
   "제가 구현한 CategoriesContainer는 서비스의 핵심 콘텐츠를 주제별로 필터링하여 사용자에게 제공하는 역할을 합니다. 초기에는 빠른 프로토타이핑을 위해 로컬 목업 데이터를 사용했지만, 서비스 확장성을 고려하여 현재는 Supabase 실시간 데이터베이스와 연동된 동적 쿼리 방식으로 고도화했습니다."

2. 핵심 로직: 영문 Key와 한글 검색어의 매핑 (가장 중요한 부분)
   "이 컴포넌트에서 가장 신경 쓴 부분은 코드의 안정성과 데이터의 정확성 사이의 연결입니다. UI 상태 관리에는 영문 ID인 key를 사용하여 오타를 방지하고 로직을 명확히 했습니다. 하지만 실제 DB에는 한글 카테고리명이 저장되어 있기 때문에, 사용자가 탭을 클릭하면 mockList에서 해당 key에 매칭되는 한글 name을 찾아 통역 과정을 거친 뒤, Supabase의 ilike 연산자를 통해 부분 일치 검색을 수행하도록 설계했습니다. 이를 통해 카테고리가 여러 개인 게시글도 누락 없이 불러올 수 있습니다."

3. 최적화 1: 캐싱 전략 (성능 고려)
   "불필요한 네트워크 요청을 줄이기 위해 **상태 기반의 캐싱 객체(cache)**를 도입했습니다. 한 번 불러온 카테고리 데이터는 상태에 저장되어, 사용자가 이전에 눌렀던 탭을 다시 클릭할 경우 서버 통신 없이 즉시 화면에 렌더링되므로 훨씬 부드러운 사용자 경험(UX)을 제공합니다."

4. 최적화 2: 메인 페이지 노출 제한 및 더보기 기능
   "메인 페이지의 가독성을 위해 Supabase 쿼리 단계에서 .limit(3)을 걸어 데이터 전송량을 최적화했습니다. 더 많은 정보가 필요한 사용자를 위해 하단에 '더보기' 버튼을 배치했으며, 이때 activeKey에 따른 한글 카테고리명을 URL 파라미터로 안전하게 인코딩하여 상세 검색 페이지로 연결되도록 구현했습니다."

5. 마무리: 예외 처리와 안정성
   "마지막으로 TypeScript의 unknown 에러 타입을 처리하기 위해 PostgrestError로 타입 단언을 활용하여 런타임 에러를 방지하고, 상세한 에러 로그를 남기도록 설계하여 유지보수성을 높였습니다."
